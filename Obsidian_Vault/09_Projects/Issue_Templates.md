# GitHub Issue Templates
_Last updated: 2026-07-22_

Use these as the default issue types. Create matching entries in `.github/ISSUE_TEMPLATE/` when the repo is initialized.

## Website
### Bug
- What broke?
- Expected behavior?
- URL, browser, Screenshot if useful.
- When did it start?

### Feature Request
- User story: who, what, why.
- Acceptance checklist.
- Design reference or link if any.
- Estimate: small / medium / large.

## Operations
### Inventory Task
- Audit target: item or location.
- Action: count, adjust, reorder, relocate.
- Deadline: date or cycle week.

### Automation Task
- Script/workflow target.
- Inputs/outputs or systems touched.
- Failure mode to watch for.
- Rollback plan.

## Finance
### Reconciliation Task
- Period/date range.
- Source files or folders to compare.
- Expected delta vs actual.
- Owner who approves.

### COGS / Pricing Review
- Products in scope.
- Source costs or vendor notes.
- Target margin or adjustment amount.
- Approvals needed.

## Legal
### Compliance / Permit Task
- Deadline or renewal date.
- Agency or form involved.
- Current status and gaps.
- Responsible owner.

### Document Review
- Document: privacy/terms/shipping/returns.
- Review type: annual refresh, customer change, audit finding.
- Source doc link or version.
- Approval date.

## Growth
### Growth Task
- Channel: social, local, wholesale.
- Goal: followers, leads, new accounts, placements.
- Budget/cost model if any.
- Success metrics and review date.

## Template Fields for All Issues
- Title: short and specific.
- Area label: `area:website`, `area:ops`, `area:finance`, `area:legal`, `area:growth`.
- Status tracking: link board column or project status.
- Acceptance criteria: merge-ready checklist.
- Linked docs: vault paths, GitHub issues, PRs.
