Torus Coffee Company - Admin Dashboard Blog and Content Design
Last updated: 2026-05-29

Purpose
This document defines the private admin experience for managing products, inventory, prices, product photos, blogs, content, settings, and future operational workflows.

Admin Goal
Let Torus Coffee Company manage the website without editing code for normal business tasks.

Admin Users
Initial admin users:
- Owner/admin
- Possible second admin later

Future roles:
- Admin: full access
- Editor: blog/content access, no pricing/security settings
- Inventory Manager: product/inventory access, no site settings
- Viewer: read-only dashboards, optional

Admin Security Principles
- Admin login required.
- Admin access separated from customer accounts by role.
- Strong password and 2FA where available.
- Admin-only pages must not be accessible from public navigation.
- All admin actions must be validated server-side.
- Dangerous changes should have confirmation prompts.
- Important changes should be logged.

Blog body editor options:
Option A: Markdown editor
- Simple, portable, easy to backup.
- Best for technical simplicity.

Option B: Rich text editor
- More user-friendly.
- More complex to build and secure.

Recommended approach:
Start with a clean Markdown or simple rich text editor, then improve if needed. Since the owner wants easy editing, we should evaluate a lightweight rich text editor during implementation.

Blog media requirements:
- Upload featured image.
- Add images inside posts.
- Add alt text.
- Embed videos later from YouTube/TikTok/etc. instead of hosting large video files at first.

Admin UX Requirements
- Clear save/cancel actions.
- Unsaved changes warning.
- Mobile usable, desktop optimized.
- Search and filters for product/blog lists.
- Plain language error messages.
- Confirmation before destructive actions.
- Archive instead of delete for important records.
- Export buttons for critical data.

Admin MVP Scope Recommendation
For the first true admin phase, build:
- Login/admin role
- Product list/editor
- Inventory quick editor
- Blog list/editor
- Image upload for products/blogs
- Site settings for contact/social/announcement
- Basic export

Do not build everything at once.

Open Decisions
1. Markdown editor or rich text editor for blogs.
2. Whether Phase 1 has admin dashboard or product data is edited more manually.
3. Whether media uploads go to Supabase Storage immediately.
4. Who besides owner gets admin access.
5. Whether to include contact inbox in admin or email-only first.

Recommended Decision
Build the public selling site first with the data model in mind, then build admin as the next major phase. If build time allows, create a minimal admin product/inventory editor early because it will reduce manual work and mistakes.
